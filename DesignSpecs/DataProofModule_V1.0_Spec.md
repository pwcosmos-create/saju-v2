# 🎨 디자인 시스템 컴포넌트: Data Proof Module (DPM) V1.0

## 📌 목적 및 역할
리드 마그넷 페이지의 핵심 섹션으로, 단순 콘텐츠 나열이 아닌 '데이터 증명'을 통해 사용자의 신뢰도를 극대화하고 체류 시간을 의도적으로 증가시키는 컴포넌트입니다. 모든 디자인은 **"시스템적 통제권 확보"**라는 핵심 메시지를 데이터 기반으로 증명하는 데 집중합니다.

## 🎨 비주얼 가이드라인
*   **배경:** Primary Color (Midnight Blue: `#0A1931`)를 유지하여 섹션의 무게감을 부여합니다.
*   **강조색:** Deep Copper (`#B8860B`)는 KPI 수치와 CTA 버튼에만 제한적으로 사용하여 핵심 행동을 유도합니다.
*   **흐름:** Clear Sky Blue (`#ADD8E6`)를 배경 요소 간의 연결선, 그래프의 상승 추세, 데이터 흐름 애니메이션(Flow)에 집중 사용합니다.

## 🧱 레이아웃 구조 (Grid System: 3 Columns)
DPM은 총 세 개의 독립적인 'Widget'으로 구성되며, 각 위젯은 다음과 같은 역할을 수행합니다.

### 1. Widget A: [핵심 KPI Tracker]
*   **내용:** 가장 설득력이 높은 핵심 수치 1~2개를 배치합니다. (예: "평균 수익률 300% 상승", "사용자 이탈률 -45%")
*   **시각화 원칙:** Deep Copper를 사용하여 숫자를 크게 강조하고, **카운트 업(Count-up)** 애니메이션을 적용하여 사용자가 '데이터가 계산되는 과정'을 지켜보게 만듭니다. (Dwell Time 증가 유도)
*   **추적 목표:** `KPI_Widget_View` (사용자가 이 위젯에 도달/주시 함)

### 2. Widget B: [시스템 Flow Visualization]
*   **내용:** '문제 발생' $\rightarrow$ '우리의 시스템 도입' $\rightarrow$ '최종 성공 상태'의 흐름을 간결한 다이어그램으로 표현합니다.
*   **시각화 원칙:** Clear Sky Blue로 연결되는 화살표와 계층 구조를 사용하며, 단계별(Step-by-step)로 정보가 점진적으로 노출되어야 합니다. (시스템적 통제권 상징).
*   **추적 목표:** `Flow_Visualization_View` (사용자가 흐름 다이어그램을 끝까지 읽었는지 추적)

### 3. Widget C: [Proof Snippet & Pain Point Hook]
*   **내용:** 가장 강력한 근거(고객사 사례, 통계청 자료 인용 등)를 작은 카드 형태로 배치합니다. 이 섹션은 '미진한 정보'를 담아 궁금증을 유발하는 것이 중요합니다.
*   **시각화 원칙:** 배경에 은은하게 흐릿한 (Ghosted) 텍스트나 대비되는 색상의 아웃라인으로 처리하여, "이것 말고도 더 많은 데이터가 있다"는 느낌을 주어 스크롤을 아래로 강제 유도합니다.
*   **추적 목표:** `Proof_Snippet_Click` (사용자가 클릭하거나 마우스를 올리는 행위)

## 💻 개발팀 연동 지침 (코다리 요청 사항)
1.  DPM 전체 영역에 대해 `scroll_deep_to_proof_section` 이벤트를 감지하고, 해당 이벤트 발생 시 스크롤 깊이(Depth)를 측정하여 기록할 것.
2.  Widget A의 핵심 수치(`KPI`)는 단순히 텍스트가 아닌 **애니메이션 기반 카운트 업**을 적용하여, 사용자의 체류 시간을 늘리고 데이터 증명의 느낌을 강화해야 함. (필수).
